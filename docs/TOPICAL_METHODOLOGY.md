# თემატური ენციკლოპედიის მეთოდური დოკუმენტი

> ეს დოკუმენტი არის საფუძველი, რომლის მიხედვითაც თემატური ენციკლოპედიის
> ხარისხის პრობლემა 100%-ით ამოიწურება. განვითარების გეგმა
> (`TOPICAL_ROADMAP.md`) ამ დოკუმენტზეა აგებული.

## 1. პრობლემის ფუნდამენტური არსი

### 1.1 რა არის თემატური ენციკლოპედია

თემატური ენციკლოპედია (Topical Bible) არის ბიბლიის მუხლების ინდექსი
თემების მიხედვით. მომხმარებელი ეძებს თემას (მაგ: "რწმენა", "ლოცვა",
"აარონი") და იღებს ყველა მუხლს რომელიც ამ თემას ეხება.

წყაროები:
- **Nave's Topical Bible** - 5,000+ თემა, 100,000+ მუხლის რეფერენსი
- **Torrey's New Topical Textbook** - დამატებითი თემები

### 1.2 სტრუქტურა

```
თემა (topic)
├── სახელი (name_en, name_ka)
├── slug (უნიკალური იდენტიფიკატორი)
├── source (nave | torrey)
├── verse_count (სულ მუხლი)
└── entries[] (ენტრიები)
    ├── label (შინაარსობრივი კითხვა/აღწერა)
    └── verses[] (მუხლის რეფერენსები)
        ├── book (წიგნის slug)
        ├── chapter
        ├── vs (დასაწყისი მუხლი)
        └── ve (დასრულება მუხლი)
```

## 2. რატომ ვერ მოგვარდება regex-ებით

### 2.1 ქართული ენის ბუნება

ქართული აგლუტინაციური ენაა. ერთი ინგლისური წინადადება ქართულში
მრავალი სტრუქტურით შეიძლება ითარგმნოს:

```
ინგლისური: "Meets Moses in the wilderness"

სიტყვა-სიტყვა: "ხვდება მოსეს უდაბნოში"
სწორი:        "მოსესთან შეხვედრა უდაბნოში"
ალტერნატივა:  "მოსეს შეხვდა უდაბნოში"
```

### 2.2 რას ვერ აკეთებს regex

- სიტყვათა წყობის ინვერსია (წინადადების რესტრუქტურირება)
- ზმნის ფორმის შეცვლა (ხვდება -> შეხვედრა)
- წინდებულის კონტექსტზე დამოკიდებული არჩევა
- მრავალმნიშვნელოვანი სიტყვების დისამბიგუაცია
- იდიომატური გამოთქმები

### 2.3 regex-ის შეზღუდვები (ექსპერიმენტულად დადასტურებული)

არსებული გრამატიკული ძრავი (`topical_translate.py`) იყენებს:
- მეტობითი ბრუნვის ტრანსფორმაციას ("X of Y" -> "Y-ის X")
- პოსტპოზიციების გადაყვანას ("in X" -> "X-ში")
- სიტყვების ლექსიკონურ ჩანაცვლებას

**შედეგი:** სიტყვები სწორად ითარგმნება, მაგრამ წინადადების
სტრუქტურა რჩება ინგლისური - რაც ქართულში არაბუნებრივია.

## 3. სწორი მეთოდოლოგია: სამდონიანი მიდგომა

### დონე A: სტრუქტურული პატერნები (regex)

**გამოყენება:** მარტივ, განმეორებად სტრუქტურებზე.

30-40 ძირითადი პატერნი რომლებიც ფარავს ხშირ კონსტრუქციებს:

| ინგლისური პატერნი | ქართული ეკვივალენტი | ხშირი? |
|---|---|---|
| "X of Y" | "Y-ის X" | ძალიან |
| "Called to/as X" | "მოწოდებული X-ად" | ხშირი |
| "Sent as X" | "გაგზავნილი X-ად" | ხშირი |
| "Meets X in Y" | "X-თან შეხვედრა Y-ში" | საშუალო |
| "Is the X of Y" | "არის Y-ის X" | საშუალო |
| "Commanded to X" | "ბრძანებული X-ს" | საშუალო |
| "Lineage of X" | "X-ის წარმომავლობა" | ხშირი |
| "Wife of X" | "X-ის მეუღვე" | ხშირი |
| "Son of X" | "X-ის ძე" | ძალიან |
| "King of X" | "X-ის მეფე" | ძალიან |

**მოსალოდნელი ეფექტი:** <1% (მხოლოდ ცხადი შეცდომები).

**დასკვნა (ექსპერიმენტულად დადასტურებული):** მარტივი "X of Y" შემთხვევები უკვე სწორად არიან თარგმნილი არსებული ძრავით. რთული შემთხვევები (გრძელი წინადადებები) regex-ით ვერ დაიფარება. ეტაპი 4-ის რეალური ეფექტი არის 29 ცხადი შეცდომის გასწორება (0.07%).

**შეზღუდვა:** რთული, კომპოზიტური წინადადებები ვერ დაფარა. ექსპერიმენტულად დადასტურდა რომ მარტივი შემთხვევები უკვე სწორად არის თარგმნილი.

### დონე B: ბიბლიის ტექსტიდან გენერაცია

**გამოყენება:** მოკლე label-ებზე (1-3 მუხლი), სადაც label არის
მუხლის შესახებ აღწერა.

**ლოგიკა:**
1. აიღე ინგლისური label
2. აიღე იმ label-ის მუხლების ქართული ტექსტი verses.json-იდან
3. გამოიყენე მუხლის ტექსტი ან მისი ნაწყვეტი label-ად

**მაგალითი:**
```
თემა: "faith" (რწმენა)
label: "Is the substance of things hoped for"
მუხლი: ებრაელთა 11:1
ქართული ტექსტი: "რწმენა არს იმედოვანთა საქმეთა გულდასმა..."

ახალი label: "რწმენა - იმედოვანთა საქმეთა გულდასმა"
```

**მოსალოდნელი ეფექტი:** 20-30% label-ის 100% ქართული გენერაცია.

**შეზღუდვა:** გრძელი label-ები (10+ მუხლი) სადაც label არის
შეჯამება, არა ციტატა.

### დონე C: ხელით კურაცია (top თემები)

**გამოყენება:** ყველაზე ხშირად ნახული თემების ყველა label-ზე.

**პრიორიტეტი:** ტოპ 5000 თემა (verse_count-ის მიხედვით) - ეს
ფარავს მომხმარებლის 80%-ის ძიებებს.

**მოსალოდნელი ეფექტი:** დანარჩენი 20-30% label-ის სრულყოფილი თარგმანი.

### დონე D: დარჩენილი label-ები (fallback)

დონე A+B+C-ის შემდეგ დარჩენილი label-ები რჩება არსებულ
მანქანურ თარგმანზე. ეს არის მისაღები fallback იშვიათი თემებისთვის.

## 6. ხარისხის კონტროლის სისტემა

### 6.1 label-ის ხარისხის ქულა (0-100)

| კრიტერიუმი | ქულის კლება |
|---|---|
| ინგლისური სიტყვა (3+ სიმბოლო) | -10 თითო |
| ზმნა წინადადების დასაწყისში | -10 |
| ბრუნვის შეცდომა | -15 |
| ძალიან გრძელი (>200 სიმბოლო) | -10 |
| ცარიელი ან ძალიან მოკლე (<5) | -50 |
| ტრანსლიტერირებული სიტყვა | -20 |

### 6.2 მიღებული ზღვარი

- **90-100:** სრულყოფილი (დატოვე)
- **70-89:** კარგი (დატოვე, შესაძლო მცირე გასწორება)
- **50-69:** საშუალო (გასასწორებელი)
- **0-49:** ცუდი (აუცილებლად გადათარგმნე)

### 6.3 ავტომატური შემოწმება

ყოველ ცვლილების შემდეგ გაუშვი:

## 7. ქართული გრამატიკის წესები (ბიბლიური კონტექსტი)

### 7.1 მეტობითი ბრუნვა
"X of Y" -> "Y-ის X"
- "King of Israel" -> "ისრაელის მეფე"
- "Lineage of Aaron" -> "აარონის წარმომავლობა"

### 7.2 პოსტპოზიციები
- "in X" -> "X-ში"
- "from X" -> "X-დან"
- "by X" -> "X-ის მიერ"
- "for X" -> "X-თვის"
- "to X" -> "X-ს" / "X-მდე"
- "with X" -> "X-თან" / "X-ით"
- "against X" -> "X-ის წინააღმდეგ"

### 7.3 სახელების ფუძე
- ეგვიპტე -> ეგვიპტის (არა ეგვიპტეის)
- მოსე -> მოსეს
- პავლე -> პავლეს
- იესო -> იესოს

### 7.4 ბიბლიური სახელები (ქართული ტრადიცია)
- აბრაამი (არა აბრაჰამი)
- მოსე (არა მოზესი)
- იესო (არა ჯესუსი)
- დავითი (არა დევიდი)
- იოანე (არა ჯონი)

### 7.5 რიცხვის შეთანხმება
- მხოლობითი/მრავლობითი შეთანხმებული უნდა იყოს
- მეფენი (არა მეფე), ხალხი (არა ხალხები)

### 7.6 ზმნის დრო
- წარსული მონაწილე: "exhorted" -> "დარიგებული" (არა "დარიგებს")
